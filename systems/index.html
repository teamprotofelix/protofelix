AI 시스템 설계대

"원하는 능력은 어떤 시스템 구조를 요구하는가?"

읽기 시간 약 10분 · 내용 성격: 아키텍처 설계 도구 · 실행 모드: RULE_BASED(+가정 기반 비용) · 검토일 2026-09-20

01이곳에서 무엇을 얻는가

입력·검색·메모리·모델·규칙 검사·도구·평가·인간 승인·출력의 아홉 블록을 버튼으로 조합해 파이프라인을 설계합니다. 블록 연결은 데이터 타입과 권한에 따라 검사되고, 비용은 실제 가격이 아닌 사용자 입력 기반 가정값으로 계산됩니다. 결과는 architecture.json과 Markdown 명세로 내보냅니다 — 실제 도구를 실행하지 않습니다.

워크플로(고정 파이프라인)와 에이전트(모델이 경로를 결정)의 차이는 Building Effective Agents를 기준으로 설명합니다.

02블록 조합

블록 추가 (버튼으로 조작 — 드래그 없이 키보드로도 가능):

파이프라인이 비어 있습니다. 블록을 추가하거나 프리셋을 불러오세요.

03결과 설명과 가장 강한 반론

관찰한 것 / 추론한 것 / 아직 모르는 것

관찰한 것: 블록 순서·권한 검사 경고·가정 비용 합계 (브라우저 계산).
추론한 것: 경고는 편집된 설계 상식입니다 — 실제 시스템의 위험은 구현·테스트에서 드러납니다.
아직 모르는 것: 비용은 내가 넣은 가정값의 산물이며 실제 가격이 아닙니다.

실패 조건: 설계도가 있으니 안전하다고 믿는 것입니다. 도구 블록은 실행 전 인간 승인, 평가 블록은 결과의 측정 조건, 출력 블록은 외부 영향의 구분을 요구합니다 — 누락된 평가·권한 경고를 무시한 설계도는 JSON으로 아름답게 저장되어도 위험합니다.

다음 질문 — 쉬운: "내가 쓰는 도구는 어느 블록 조합에 가장 가까운가?" · 반대: "블록이 많을수록 좋은 시스템인가?" · 먼 분야: "건축 도면의 '검토 날인' 제도는 AI 설계 문서의 승인에 무엇을 시사하는가?"
