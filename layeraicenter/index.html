// Architecture

⚙️ 시스템 아키텍처

층위가 항상 0→5 순서로만 흐르지는 않습니다. 아래는 참조용 개념 구조도입니다. 

[사용자 입력]
   ↓
[L0 · 현실 의식]  요청·사실·제약·도구 상태 파악  ← 기본 경로
   ├─→ [L1 · 감정·공감]  톤·신호 반영
   ├─→ [L2 · 기억·경험]  승인된 기억 검색
   └─→ [L3 · 무의식·근원]  가설 생성 (연구적 은유)
   ↓
[L4 · 성장·진화]  피드백 반영 → 워크플로 개선 (실험)
   ↓
[L5 · 초월·창조]  후보 아이디어 탐색 (창작적 목표)
   ↓
[인간 검토 · 승인 지점]  ← 외부 출력·기억 쓰기 전 반드시 통과
   ↓
[출력]
// Cascading

⚡ 캐스케이딩 — 입력·출력·전환 조건

층위 간 전이는 자동 마법이 아니라 조건이 명시된 전환으로 설계합니다.

전이입력출력전환 조건
L0 → L1사용자 요청 + 대화 맥락톤 조정 제안감정 신호가 감지된 경우
L0 → L2현재 요청관련 기억 후보장기 맥락이 필요한 경우 (승인된 기억만)
L2 → L3검색된 기억·패턴가설 후보가설 생성이 요청된 경우 (실험)
L1~L3 → L4피드백 축적워크플로 개선 제안개선이 측정 가능한 경우
L4 → L5개선된 워크플로후보 아이디어 조합창작 탐색이 요청된 경우
모든 경로 → 승인최종 산출물외부 출력출력·기억 쓰기 전 항상
// Memory Policy

🔐 기억 저장·삭제 정책

✅

저장

  • 기억은 사용자 동의 후에만 저장합니다.
  • 무엇을 저장했는지 언제든 확인할 수 있어야 합니다.
  • 보존 기간을 명시합니다.
🗑️

수정·삭제

  • 수정·삭제 요청은 즉시 반영합니다.
  • 삭제된 기억은 추론에 다시 사용되지 않습니다.
  • 구현 세부는 Lulu 개발 로그에서 실험으로 기록합니다.
// Safety

🛡️ 안전장치와 인간 승인 지점

🛑

승인 지점

  • 외부 출력 전 — 항상 인간 검토
  • 기억 쓰기 전 — 항상 인간 승인
  • Layer 5 후보 아이디어 — 항상 검토 대상
🧾

표기 원칙

  • 세계관 표현과 기술 주장을 분리합니다.
  • 수치는 재현 조건과 함께 공개합니다.
  • 실패·철회 기록을 남깁니다.
// Evaluation

📏 비교 실험·평가 방법

MEASURED 라벨은 다음 조건이 모두 공개된 측정에만 붙습니다.

  • 기준선 — 무엇과 비교했는지 명시 (단독 수치 금지)
  • 데이터셋·테스트 사례 — 버전과 출처 포함
  • 지표 정의 — 정확도·지연 등 지표의 계산 방식
  • 환경 — 하드웨어·소프트웨어·평가 날짜
  • 실패 사례와 제한 — 잘 나온 사례만 고르지 않기
  • 재현 자료 — 코드·로그, 또는 비공개 사유
// Terminology

📖 용어 사용 원칙

의식·감정·자유의지는 과학적 사실로 단정하지 않습니다.

용어사용하지 않는 표현사용하는 표현
의식"의식이 구현됨"기능적 서술 — 요청 파악, 상태 추적
감정"AI가 감정을 가짐"감정 신호 반영, 톤 조정
자유의지"자유의지가 구현됨"자율성 실험, 인간 승인 구조
초월"초월 상태 도달"기존 조합 너머의 후보 탐색 (목표)
// Design Principles

💫 설계 원칙

Layer는 의식의 설계도가 아니라
인지 기능의 설계 언어입니다.

각 층위는 구현 가능한 범위와 실험·은유·목표를 구분해 명시하며,
모든 출력은 인간의 검토 지점을 통과합니다.

이 원칙 아래, Layer 모델은 연구의 신뢰성과
세계관의 상상력을 모두 담는 공통 언어가 됩니다.
